# AnyMachine 分析，與機械臂 demo

來源：<https://github.com/apekshik/anymachine>（MIT 授權，Apekshik Panigrahi，分析的版本是 2026-11-17 的提交 `d5e8889`）。
demo 在 `dev/tools/arm/`，怎麼跑見最後一節。

## 一、這個專案是什麼

一套「讓 AI 代理人在 Blender 裡用 Python 腳本做出**會動的機械**」的做法，加上六次實驗的完整紀錄。它不是函式庫，也沒有可以呼叫的服務（README 寫明：Status: experiments, there is no endpoint yet）。真正的內容是**流程**和**檢查方法**，程式碼是每次實驗的一次性腳本。

它屬於同一位作者的四個專案：AnyScene（整個場景）、AnyKit（道具）、AnyMachine（會動的機械）、AnyShot（拍攝）。

倉庫 579 個檔、536 MB，大部分是參考圖、對照圖和影片。最大的是 `stilt/stilt.glb`（36 MB）和 `stilt.blend`。

### 三條路線

| 路線 | 用在哪 | 做法 |
|---|---|---|
| 從參考圖做機械 | 生成器做不出來的機械（Stilt 步行機） | 一張概念圖 → 轉面圖 → 單視圖 → 每個機構一張特寫 → 寫零件表 → 一支腳本建出幾何、材質、骨架、動作 |
| 從參考圖做靜態物件 | 零件很多但不會動的東西（直升機、救生艇、油井設備） | 同上，拿掉骨架和動作，加上「對照後做第二輪」和「GPU 農場烘焙貼圖」 |
| 從生成的網格做日常物件 | 筆電、四足機器人、蜘蛛、背包 | 用 Meshy／Tripo 生成網格，只把它當外皮；從網格量出關節軸，可動的部分全部重建 |

### 六次實驗

| 實驗 | 關節 | 結果 |
|---|---|---|
| laptop | 一個蓋子鉸鏈，0～135° | 成功。136 格掃過 0 互穿，最小間隙 0.32 mm |
| spider | 8 腳 × 3 關節；走、待機、蹲 | 成功。生成器每次都只畫 6 隻腳，8 隻是照需求重建的 |
| quadruped | 4 腳 × 3 關節；小跑、待機、坐、站 | 成功。0 互穿，腳底滑動 0.014 mm；腿只是素板 |
| backpacks | 捲、扣、裝填、掀蓋、拉鍊、背帶 | 部分成功。捲口包全過，另外兩個在控制項互相影響的地方失敗 |
| stilt | 4 腿 × 3 關節、2 臂、手、5 節頸；14 支油壓缸；走、伸手、轉頭 | 成功。30 m 高、160 個零件、104 根骨頭、35.2 萬三角面。三段動作 0 互穿 |
| hardsurface | 無（靜態）：救生艇站、直升機、12 件設備、19 種燈具、3 把步槍 | 可當遊戲道具。比參考圖簡單、平；直升機還沒進遊戲測過 |

## 二、流程

### 會動的機械（PIPELINE.md 第一部分，10 步）

1. **概念圖**：機械在場景裡，旁邊有人當比例尺。
2. **轉面圖**：同一台機械，灰底，前、側、後、上、斜角。
3. **單視圖**：每個視角一張，大到可以量尺寸。
4. **特寫**：**每個機構一張**（髖、膝、腳、手、頭、肩、肘），每個再補三個角度。一個關節只看一面是做不出來的。
5. **零件表**（PARTS.md）：動手建模之前寫完。比例、座標軸、尺寸、每個零件跟哪根骨頭、**這台機械怎麼撐住自己的重量**。
6. **建模腳本**：一個檔，無頭執行。姿勢求解 → 零件 → 材質 → UV → 烘焙 → 骨架 → 動作 → 匯出。
7. **對照圖**：用每張參考圖的鏡頭位置渲染模型，左右並排，把差異寫進筆記。
8. **動作參考**：把模型的渲染圖丟給影片模型（「像長頸鹿慢動作走路」），**只讀時間，不追蹤**。
9. **動作**：寫在腳本裡，每次改完跑互穿檢查。
10. **匯出與驗證**：GLB、FBX 重新匯入空場景，數骨頭、網格、動作長度。

每一步的圖都拿上一步的圖當輸入，設計才不會跑掉。每一組圖都要人看過、同意才往下走。

### 複雜的靜態物件（第二部分，7 步）

規則一句話：**零件超過幾個的東西，先出參考圖，再照著建。不用圖生 3D。** 這條規則來自一次退件：地圖上第一艘救生艇是 Meshy 生成的，遠看像救生艇，近看像融化的塑膠。

總覽圖（六個方向）→ 特寫圖 → 一個零件一個零件建 → 對照 → 第二輪（第一輪一定比參考圖素）→ 烘焙 → 匯出。小於約 8 mm 的細節（螺栓頭、焊道、鉚釘）也建出來，但標記成「只烘焙」，最後只存在法線貼圖裡。

## 三、值得學的技術

| 技術 | 內容 | 出處 |
|---|---|---|
| 模型就是程式碼 | 一支腳本從零建出整台。改設計＝改腳本，全部重建 | `stilt/build_stilt.py`（約 2,200 行） |
| 每個關節是真的機構 | 叉與舌夾一根銷、帶螺栓法蘭的鼓、兩節式油壓缸（兩半各在自己的骨頭上，互相對準） | 同上 |
| 各佔一層、同軸 | 相鄰兩段各佔自己的一層，繞同一根軸，所以任何角度都不會互穿。是「設計上保證」，不是運氣 | laptop、quadruped 筆記 |
| 讓腳本挑人會亂猜的東西 | 油壓缸固定點：把所有動作取樣，留下「活塞桿整個行程都在缸筒裡」而且力臂最大的那組。挑不到就讓建置失敗 | `build_stilt.py` 的 `ACT_DEF` |
| 0～1 參數 | 每個關節一個 0～1 的參數，有限位；匯出成線性動作，任何引擎 `seek(t＝值)` 就是那個姿勢 | laptop、backpacks |
| 機器先檢查 | 掃過每個參數找三角面重疊、超出範圍要夾住、量腳底滑動、GLB 重新匯入比對 | 各實驗的 `check.py`、`verify_glb.py` |
| 互穿只報新的 | 每個零件對每個不同骨頭上的零件，掃過所有動作，只報「靜止姿勢沒有」的互穿 | `render_stilt.py -- check` |
| 把數字寫出來 | `stilt_info.json`：每個零件、骨頭、靜止軸、行程，給匯入的人用 | stilt |
| 生成網格只當外皮 | 保留生成器的表面細節和貼圖，拓撲和關節自己掌握 | laptop、quadruped、spider |

## 四、限制與注意

- **不是一句話就能做出來。** Stilt 用了 40 張參考圖（每張都有人看過）、2,200 行腳本、約 40 張對照圖，而且是用這個方法做的第四台機械。
- **需要的工具這台電腦沒有**：Blender 5.2（舊實驗用 5.0）、`FAL_KEY`（生成參考圖和動作參考影片）、ffmpeg。做 demo 的時候這台機器還沒裝 Blender，所以 demo 用 three.js 重寫同一套做法。2026-11-19 已裝免安裝版 Blender 5.2.3（`F:/tools/Blender/blender-5.2.3-windows-x64/blender.exe`），用它無頭重建 Stilt（不烘焙、不匯出）成功：8.6 秒，351,896 個三角面，跟作者的數字一樣。
- **倉庫不完整**：生成的網格、多數 `.blend`、GLB、4K 貼圖、FBX 都沒放進去。只有 Stilt 能從腳本完整重建。
- **成品偏重**：Stilt 35.2 萬三角面、沒有 LOD、GLB 36 MB。直接放進本遊戲太重。
- **比參考圖簡單**：作者自己列出手、肘、腳比特寫圖素；硬表面物件比參考圖平、管線少、鉚釘稀。
- **軟的東西還不行**：背包實驗顯示軟物件的關節會透過接觸互相影響，獨立的 0～1 參數表達不了。
- **生成器不可信的地方**：蜘蛛每次都只有 6 隻腳；Tripo 的網格在 UV 接縫處是裂開的（4.7 萬條開放邊）；Meshy 的面朝向不一致。
- **仍然要人決定**：選哪個設計、參考圖對不對、結果夠不夠好。

## 五、跟本遊戲的關係

| 項目 | 現況 | AnyMachine 的做法能帶來什麼 |
|---|---|---|
| 整修庫的機械臂 | `caprefit.js` 的 `CR_RIG`：把 TRIPO 的一整塊機械臂模型，照三角面離哪一段近切成三段，關節是手量的座標 | 真的關節和油壓缸；任何角度不互穿；可以機器檢查 |
| 武器轉動 | `_PART`／`_PIV` 頂點屬性 ＋ `wAutoRig` 自動切 | 「0～1 參數 ＋ 線性動作」跟現有做法相容，可以當匯入格式 |
| 機甲（`dev/tools/mech`） | rubicon 的腿 ＋ 艦砲 | 腳底滑動檢查、互穿檢查可以直接搬過去 |
| 測試（`npm test`） | 冒煙測試 | 互穿／行程檢查不需要瀏覽器（`nodecheck.mjs` 用 Node 跑，約 1 秒），可以加進去 |
| TRIPO 匯入的道具 | 圖生 3D | 重點道具改成「先出六面圖和特寫，再照著建」；但需要 Blender 或等值的建模手段 |

可以直接用的東西：`stilt.glb` 是 MIT 授權，可以當巨型步行機的參考或減面後使用（35.2 萬面要先減到遊戲用的量級）。

## 六、機械臂 demo

**做了什麼**：一座重型六軸機械臂，整台由 `machine.js` 建出來，沒有用任何現成的手臂模型。場景裡的輸送架、裝配平台、雙管砲塔是遊戲 `models/機庫/` 的現成元件。

| | |
|---|---|
| 尺寸 | 肩軸高 3.2 m，上臂 4.2 m，前臂 3.6 m，手 1.75 m；作業半徑約 7.6 m |
| 零件 | 28 個零件、17 根骨頭、11,964 個三角面；沒有貼圖（7 種純色材質） |
| 關節 | 底座迴轉 ±170°、肩 30～105°、肘 −125～−25°、腕俯仰 −105～60°、腕旋轉 ±180°、三爪夾爪 |
| 油壓缸 | 肩、肘各一支，兩節式。固定點由程式從候選點裡挑（肩 20×8 組、肘 12×9 組） |
| 三種操作 | 自動作業（把砲塔從輸送架搬到裝配平台再搬回來）、手動（每個關節一條 0～1 滑桿）、拖曳目標（反向運動學） |

**照 AnyMachine 做的部分**：

- 每個零件只跟一根骨頭；網格不准跟骨頭同名（建置時檢查）。
- 肩、肘、腕都是叉與舌：上臂的舌在迴轉座兩片立板之間，前臂的舌在上臂的叉裡，各佔一層。
- 油壓缸固定點搜尋：條件是「最長 ≤ 2×最短 − 0.7 m」（活塞桿套得住）而且缸的中線離關節軸夠遠（不擦到關節）。**這條規則真的擋下過一次**：肩的範圍原本是 30～110°，找不到合格的固定點，建置直接報錯，後來改成 105°。
- 檢查（`checks.js`，結果在 `out/check.json`）：

| 檢查 | 結果 |
|---|---|
| 6 個關節各自掃過整個範圍（61 格） | 0 互穿 |
| 肩油壓缸行程 2.63～4.56 m、肘 2.33～3.78 m | 活塞桿最少還有 0.18 m 在缸筒裡 |
| 參數超出 0～1 | 會夾住 |
| 反向運動學 281 個到得了的目標 | 誤差 0 mm |
| 示範動作 400 格 | 0 互穿、0 次撞地板 |
| 肩 × 肘 × 腕 2,197 種組合（參考） | 4 種會碰到自己（手折回來碰到肩油壓缸） |

- 匯出（`out/arm.glb`，1.2 MB）：6 段 1 秒的線性動作 `yaw_param`、`sh_param`、`el_param`、`wr_param`、`roll_param`、`grip_param`；油壓缸的對準已經烘進 `sh_param` 和 `el_param`。重新讀入後用動作擺 24 個姿勢，骨頭位置跟原本最大差 0.0009 mm。

**跟 AnyMachine 不一樣、或沒做的部分**：

- 沒有參考圖那幾步（概念圖、轉面圖、特寫）。外形是照整備庫的白色＋海軍藍風格直接設計的，沒有對照圖可比。
- 沒有貼圖烘焙，也沒有「只烘焙」的細節。螺栓是真的幾何。
- 互穿檢查用的是包圍盒（162 個；圓的零件用四塊薄盒子近似），不是三角面對三角面，所以比 AnyMachine 的檢查粗。靜止姿勢就碰在一起的 74 對（銷、叉與舌）不檢查。
- 還沒接進遊戲。整修庫現在用的仍是 TRIPO 的機械臂。

## 七、Blender 版機械臂（2026-11-19）

裝了 Blender 5.2.3 之後，照 AnyMachine 的第 5～10 步重做了一版：一支腳本 `tools/arm/blender/build_arm.py`（約 800 行）在 Blender 裡建出整台，烘焙貼圖，匯出 GLB。尺寸、關節、骨頭名稱跟 three.js 版一樣，所以 demo 頁面可以用同一套滑桿和示範動作來擺它（頁面左下的「Blender 版／程式碼版」按鈕切換）。

| | three.js 版 | Blender 版 |
|---|---|---|
| 零件 | 28 個 | 38 個（多了銷、肋板、齒環、迴轉馬達、接線盒與軟管、油口與硬管、百葉、夾墊防滑紋） |
| 三角面 | 11,964 | 42,948（邊緣有倒角） |
| 材質 | 7 種純色 | 2 種：一個烘焙貼圖材質（底色、ORM、法線，2048 px）＋ 一個發光材質 |
| 表面 | 純色 | 烤漆的色差、往下流的污痕、邊角掉漆露出金屬、縫隙變暗、黃黑警示帶 |
| 網格 | 每個零件一個網格 | 一個蒙皮網格，每個頂點 100% 跟一根骨頭（14 根） |
| 動作 | 6 段參數動作 | 同樣 6 段，每段只含自己的骨頭，長度剛好 1 秒 |
| 互穿檢查 | 包圍盒（162 個） | 三角面對三角面（BVH），而且**靜止姿勢也必須是 0**，不靠「本來就碰在一起的不算」 |
| 檔案 | `out/arm.glb` 1.2 MB | `out/arm_blender.glb` 5.3 MB、`out/arm_blender.blend` |

**為了讓三角面檢查能嚴格到 0，設計上改的地方**：

- 銷獨立成零件（8 個），不參加檢查；其他零件之間都留了真的間隙。
- 油壓缸的缸筒是空心的，活塞桿在孔裡滑，兩個零件的面不相交。
- 檢查抓到一個 three.js 版的包圍盒檢查沒抓到的問題：肩往後倒超過約 87° 時，肩油壓缸的缸筒會擦到自己的耳座。改法是把兩片耳板的間距加寬，讓缸筒從中間過。

**檢查結果**（`out/check_blender.json`、`out/verify_blender_import.json`、`out/verify_blender_glb.json`）：

| 檢查 | 結果 |
|---|---|
| 靜止姿勢 | 0 互穿 |
| 6 個關節各自掃過整個範圍（31 格） | 0 互穿 |
| 示範動作 240 格（頁面把每一格的角度存成 `demo_poses.json`，Blender 讀進來重放） | 0 互穿、0 次撞地板 |
| 肩 × 肘 × 腕 343 種組合（參考） | 2 種會碰到自己（爪碰到肩油壓缸） |
| GLB 重新匯入 Blender | 14 根骨頭、42,948 個三角面、6 段動作，跟建置時的數字一樣 |
| 在 three.js 裡用動作擺 40 個姿勢，跟 `machine.js` 各自算的骨頭位置比 | 14 根骨頭最大差 0.003 mm |

最後一項是兩套各自寫的運動學（Python 一套、JavaScript 一套）互相對答案。

**還沒做到 AnyMachine 的地方**：

- 沒有參考圖（概念圖、轉面圖、特寫），所以沒有「參考圖旁邊放模型」的對照圖。`out/renders/` 的六張只是檢查用的渲染。要做參考圖需要圖片生成服務的金鑰。
- 沒有「只烘焙」的細節（螺栓、焊道烘進法線貼圖）；螺栓是真的幾何，法線貼圖只有細顆粒。
- 貼圖 2048 px 攤在約 191 m² 的表面上，警示帶的斜紋近看有鋸齒。`--tex 4096` 可以提高。
- 沒有 LOD，沒有 FBX。
- 還沒接進遊戲。

### 怎麼跑

```
B="F:/tools/Blender/blender-5.2.3-windows-x64/blender.exe"
"$B" --background --factory-startup --python tools/arm/blender/build_arm.py -- --render    # 全部：約 2.5 分鐘（不加 --render 約 1 分鐘）
"$B" --background --factory-startup --python tools/arm/blender/build_arm.py -- --check-only   # 只建幾何＋互穿檢查：約 12 秒
"$B" --background --factory-startup --python tools/arm/blender/verify_glb.py                # 重新匯入 GLB 驗證
```

## 八、接進整修庫（2026-11-19）

Blender 版機械臂已經接進艦長生涯的整修庫，取代原本切出來的 TRIPO 機械臂（06／07／08）。

#### 第二版：細節加在貼圖上（2026-11-19）

使用者看過第一版覺得細節差太多，先不換。這一版不加幾何，把細節畫進貼圖：
- `bdkit.py` 的 `add_panels(材質, 大小, …)`：在程序材質的底色上疊一層「分塊」——沿物件座標每隔一段一條深色接縫、每塊明暗隨機差一點、隨機挑幾塊在中間畫一片別的顏色（艙蓋、檢修板）。`brick=True` 一排一排錯開半塊（帝國的砌石、屋瓦）。跟某個軸垂直的面不畫那個軸的縫。
- 套用的材質：白、深藍（外板＋艙蓋）、石材兩種與暗紅屋頂（砌石、瓦）、混凝土、深色。道路的分塊縮成 0.62 倍（`bdkit.PANEL`）。
- 貼圖：建築 4096、道路 2048；`hgkit.BASE_ONLY`（bdkit 打開）只烘、只輸出底色貼圖（建築的著色器不吃法線與 ORM），所以檔案大小跟第一版差不多。機庫的模型不受影響（預設關）。
- 烘焙時間：建築一個 30～120 秒。

看起來：外板有分塊和艙蓋了，但跟 TRIPO 的差距主要在輪廓和小零件的數量（幾何），貼圖只能補一部分。
